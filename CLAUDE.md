## Overview

A small .NET 10 (`net10.0`, `LangVersion preview`) ASP.NET Core GraphQL API built on HotChocolate 16.7.3. It is an early scaffold: the domain is a shop with branches, products and sales, but `Query` is still empty and nothing is wired to a data source yet. There are no tests, and the directory is not a git repository.

## Commands

```bash
dotnet run                      # serves GraphQL at http://localhost:5095/graphql (launch profile "http", opens browser, Development env)
dotnet build
dotnet watch run                # rebuild/restart on change
```

`Program.cs` ends with `app.RunWithGraphQLCommands(args)` (from `HotChocolate.AspNetCore.CommandLine`), so the app also accepts HotChocolate CLI commands instead of starting the server, e.g. `dotnet run -- schema export` to print/export the SDL.

## Architecture

- `Program.cs` — minimal hosting: `builder.AddGraphQL().AddTypes()` then `app.MapGraphQL()`.
- `Types/` — GraphQL types live here. `Query.cs` is the root (`[QueryType] public static partial class Query`); `Branch`, `Product` and `Sale` are plain C# records intended as domain/output types.
- **Source-generated registration.** `AddTypes()` is not a hand-written extension: it is generated by `HotChocolate.Types.Analyzers` (referenced as an analyzer-only package) from attributes such as `[QueryType]`. The module name comes from `[assembly: Module("Types")]` in `Properties/ModuleInfo.cs`. Consequences when adding schema members:
  - Annotate classes (`[QueryType]`, `[ObjectType<T>]`, `[MutationType]`, etc.) and keep them `partial` where the generator requires it; there is no manual `AddQueryType<...>()` registration to add.
  - Query fields are `public static` methods on `Query`; new types/resolvers are picked up automatically on build.
- `Properties/launchSettings.json` pins the dev URL to `http://localhost:5095`.

## Notes

- `shop.db` (SQLite, project root) has tables `Branch`, `Product` and `Sale` mirroring the records in `Types/` (`Sale.ProductId` → `Product.Id`, `Sale.BranchId` → `Branch.Id`), seeded with 3 branches, 10 products and 15 sales (5 per branch). It was cloned from the older `library.db`, which is now obsolete (kept only because Rider locked the file; ignore it). Column names must match the record properties. No code references the database yet; it is only used through Rider's database tool (`.idea/` data-source config) and the `sqlite3` CLI. SQLite enforces foreign keys only with `PRAGMA foreign_keys = ON` per connection.
- `obj/` and `.idea/` are build/IDE output; ignore them.
